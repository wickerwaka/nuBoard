# Mirrored-RAM 68000 fuzzing

`validation.m68000.fuzz` generates reproducible, writable 1024-byte images.
After initialization, every CPU address aliases `address & 0x3ff`, including
exception vectors and addresses previously used for harness MMIO. The two CPUs
have independent copies of the image and run sequentially, never together.

## Initial state

SHAKE-256, domain `nuBoard-68000-fuzz-v1` plus the little-endian 64-bit seed,
generates the image and initial register values. Only the first eight image
bytes are replaced: SSP is `0x400` and PC is an even address in `8..1022`.
All remaining bytes, including exception vectors, stay random.

A temporary bootstrap overlay at `0xff0000` initializes D0–D7 and A0–A6,
USP=`0x400`, and SR=`0x2700`. A7 comes from the reset SSP. Initial address
registers are even 24-bit values; data registers contain unrestricted values.
The reset PC response points at this overlay without changing image bytes.
The overlay disappears at the first program fetch of the chosen random PC.
There are no collector instructions or reserved locations in the random RAM.

## Bounded execution and comparison

The default budget is 2000 CPU clocks at 5 MHz; build 11 accepts 16–4000.
Counting starts on the first falling edge after recognition of the initial
random-PC fetch. A separate 50,000-tick watchdog includes the bootstrap.
At 4000 clocks the 32,768-record BRAM buffer depends on change compression;
it cannot hold a change on every 20 ns tick. The runner rejects truncation,
overflow, missing handoff, or incomplete
budget coverage. No PSRAM is used. Halted or stopped CPUs still consume the
clock budget; many random images will reach such states quickly.

Comparison uses one alignment epoch, then samples 20 ns before each CPU edge.
CPU outputs changing in the preceding sample interval are indeterminate,
not silently accepted. Selected data, meaningful address/FC/control signals,
completed bus transactions, and all 1024 final RAM bytes are compared.
DTACK/BERR differences remain visible. There is no per-transaction realignment
or undefined-flag masking. A difference is evidence to investigate, not by
itself proof of an fx68k defect.

Final architectural registers are **not** read back. RAM and captured bus state
are the first-pass state comparison; stopping is at a fixed clock budget, not
an instruction boundary. The harness resets the CPU at cutoff while preserving
RAM and the pre-reset capture. The socket clock continues while armed.

## Commands

Build the FPGA and simulators using the existing harness build instructions.
Build 14 is required by the current runner (the timing probes default off).
Simulation acquisition:

```sh
PYTHONPATH=host/src build/venv/bin/python -m validation.m68000.fuzz \
  --target sim --seed 0 --count 16 --cycles 2000 \
  --output build/validation/m68000/fuzz/sim-new.json
```

`--target spi-sim` exercises the mailbox path. These single-core targets verify
acquisition only, not equivalence to silicon.

With the MC68000 daughterboard fitted and 5 V exclusively selected:

```sh
PYTHONPATH=host/src build/venv/bin/python -m nuboard.cli configure \
  build/fpga/m68000/outflow/m68000.hex.bin
PYTHONPATH=host/src build/venv/bin/python -m validation.m68000.fuzz \
  --target board-pair --socket-fitted --seed 0 --count 16 --cycles 2000 \
  --output build/validation/m68000/fuzz/board-new.json
```

The runner requires receipt-matched firmware identity, VCCB initially off,
5 MHz clocks, and the qualified eight-tick responder delay. It stops at the
first difference or acquisition failure, powers off, and verifies all rails.
Use a fresh output path: images, register setup, hashes, raw captures, RAM,
transaction traces, comparison details, and cleanup status are retained.

## Debug registers (build 11)

All registers are little-endian and configuration writes require an idle core.

| Address | Access | Meaning |
| --- | --- | --- |
| `0x80` | RW16 | Fuzz enable, 0 or 1; reset default 0 |
| `0x82` | RW16 | Clock budget; RTL range 1–4000, host minimum 16 |
| `0x84` | RO16 | Bits 0/1 lane handoff; bit 2 counting; bit 3 budget complete |
| `0x88` | RO32 | Capture-tick alignment epoch |
| `0x8c` | RW16 | Even initial random PC, 8–1022 |

Host writes at `0x10000` initialize both private lane images. Bootstrap storage
is at host `0x18000`. Reads at `0x10000`/`0x20000` return model/socket RAM.
Fuzz enable must be zero for ordinary directed tests; a new configuration
restores that default. Normal pass-marker result bits do not indicate success
in fuzz mode: the runner checks the dedicated budget/handoff flags instead.

## Initial qualification, 2026-09-19

Build 10 passes the routed timing/pin gates (153 package assignments).
Bitstream SHA-256:
`013ad7ecaee5bea7567e3fd9a3b3f2bb959ad0c4de2707b0098929774e248dda`.

Seeds 0–15 at 2000 clocks each passed real MC68000P12 versus board fx68k,
and all 16 real-chip captures also matched direct Verilator simulation.
Seeds 0–3 matched direct versus SPI/mailbox simulation. The physical run took
15.85 seconds and used 4724–8064 records per capture, at most 24.7% of BRAM
capacity. Completed random-region bus transactions ranged from 14 to 393;
this is a small bring-up corpus, not broad instruction coverage.

Evidence: `build/validation/m68000/fuzz/board-build10-01.json`,
`direct-build10-01.json`, and `spi-build10-01.json` in the same directory.
The board report confirms VCCB, 3.3 V, and 1.2 V off after the run.
Regression tests independently check bootstrap register values, old-MMIO
aliasing, private memories, deterministic replay, bounds, and rejection of
deliberate comparison differences.
All 180 cases in the existing default directed physical suite also pass with
fuzz mode disabled (`build/validation/m68000/campaign/build10-board.json`).

## 4000-clock campaign, 2026-09-19

Build 11 raises the maximum budget to 4000 CPU clocks. Its routed timing and
pin checks pass; bitstream SHA-256:
`d659229698ee7b992a4d855956258e01386cebfeac861e1cb6f29f957db8f144`.
All 60 validation tests pass, including a 4000-clock acquisition regression.

Seeds 0–999 passed real MC68000P12 versus board fx68k at 4000 clocks per CPU,
with no timing, transaction, RAM, or acquisition failures. The physical run
took 1706.47 seconds (28 minutes 26 seconds). Captures used 8714–15695 records,
peaking at 47.9% of BRAM capacity. Random-region transaction counts ranged
from 11 to 855, so clock budgets should not be interpreted as instruction
coverage. All rails were verified off afterward.

The full physical report is
`build/validation/m68000/fuzz/board-build11-4000-1000.json`; the corresponding
1000-seed simulation acquisition is `direct-build11-4000-1000.json` in the
same directory. Per-seed artifacts preserve both CPU captures and RAM images.
All 1000 real-chip captures also match direct Verilator simulation; cross-check
logs are `build11-crosscheck-000-599.log` and `build11-crosscheck-600-999.log`
in the same directory. The durable summary and evidence hashes are in
`validation/m68000/fuzz-4000-qualification-2026-09-19.json`.

To repeat, configure build 11 and use a fresh output path:

```sh
PYTHONPATH=host/src build/venv/bin/python -m validation.m68000.fuzz \
  --target board-pair --socket-fitted --seed 0 --count 1000 --cycles 4000 \
  --output build/validation/m68000/fuzz/board-4000-repeat.json
```
