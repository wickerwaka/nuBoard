# Coverage audit: 1000 seeds at 4000 CPU clocks

The comparisons passed, but the unconstrained random-image campaign has
**broad opcode variety and shallow useful execution**. It is heavily weighted
toward exception handling, double-fault halts, and repeated paths. It should
not be treated as 1000 long, diverse instruction sequences.

This audit reads the saved physical MC68000 captures; no new board runs were
performed. It excludes the deterministic initialization prelude. All per-seed
artifact hashes were checked against the campaign index.

## What actually happened

| Observation | Cases / result |
| --- | --- |
| NOP words (`4e71`) in completed program-space reads | 0 |
| First instruction is illegal or an A/F-line exception | 296 / 1000 |
| Recognized exception-entry signature | 997 / 1000 |
| First recognized exception before clock 100 | 867 / 1000 |
| At least ten recognized exception entries | 569 / 1000 |
| HALT asserted for more than half the budget | 437 / 1000 |
| No completed bus transfer after clock 1000 | 432 / 1000 |
| Repeated final program-space fetch pattern | 456 / 1000 |
| Distinct program-space addresses per case | median 9; 90th percentile 23 |

Across all cases, HALT was asserted for 42.2% of the sampled random-region
time. The initial opcodes span 74 ordinary mnemonic families (ignoring size
suffixes), plus illegal/A-line/F-line cases. Initial opcode decoding records
an instruction **attempt**, not proof of successful completion.

There were 410,163 completed transactions and 189,667 writes, including 7,180
byte writes. RAM changed in 999 cases. These counts are not instruction
coverage: exception-stack writes account for a substantial part of activity.

Recognized exception entries were mainly illegal instruction (14,993), address
error (13,597), A-line (4,543), and F-line (3,909). There were also 202 CHK,
four divide-by-zero, and one trace exception signatures.

## Concrete instruction samples

These are initial instructions at known entry points, with corresponding
operand transactions in the physical capture:

| Seed | PC | Instruction | Observed behavior |
| --- | --- | --- | --- |
| 0 | `0x20e` | `MOVE.B D7,(A3)` | Byte write at `0x6fabca` |
| 61 | `0x1b8` | `MULU.W -(A6),D0` | Reads `0x4add` from `0x8dcdc2`, then proceeds |
| 28 | `0x2a4` | `DIVU.W -(A1),D0` | Reads nonzero divisor `0x7406` from `0x2c8dc2`, then proceeds |
| 95 | `0x126` | `BCHG D7,(A4)` | Byte read/modify/write at `0x8cfc06` |
| 608 | `0x13c` | `MOVEM.W D0-D3/A0/A2-A3/A5-A6,$694a.W` | Nine consecutive word writes at `0x694a..0x695a` |

Seed 0 continues with `AND.L D0,(A3)`, `ADD.L D4,-(A4)`, and
`NOT.B ($4fc5,A1)`; the captures contain the corresponding operand reads and
writes. This demonstrates useful instruction execution, not just fetch traffic.

There is also a clear degenerate loop: seed 65 reaches `BGE $212` (`6cfe`)
at address `0x212`. It repeatedly fetches `0x212` and prefetches `0x214` for
almost the entire remaining budget. The prefetched instruction at `0x214`
must not be counted as executed.

## Method and limits

The audit uses physical `run.trace`, RLE pin captures, original images, and
final RAM. Musashi raw-byte disassembly is used only at known initial PCs.
A/F-line words are explicitly classified as exceptions on the MC68000, even
where the disassembler prints later-generation MMU mnemonics.

An exception signature requires three immediately preceding supervisor word
writes followed by a supervisor word-read pair at a vector address. This is
strong bus evidence, not a full exception decoder; missing signatures do not
prove absence of exceptions. Tail repetition is four repeats of a 1–32-word
program-read pattern. Program-space reads include prefetch, extension words,
and PC-relative operands; they are not retired instructions. Address counts
and loop detection are therefore explicitly proxies, not instruction counts.

## Recommendation

Keep this raw-random campaign as an exception/robustness test. Add a separate
constrained instruction generator with legal opcode/operand combinations,
controlled exception targets, and bounded branches. Measure opcode/addressing
mode coverage and reject or shorten runs dominated by halts or tiny loops.
Do not silently change the meaning of the existing all-random image suite.
Exact execution coverage would additionally require instruction-boundary
instrumentation in simulation, correlated against the physical bus trace.
