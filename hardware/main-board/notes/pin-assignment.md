# nuBoard T120F484 pin assignment

Generated by `scripts/nuboard_pin_assign.py` from the geometry in
`nuBoard.kicad_pcb` and `t120f484.csv`. Regenerate rather than edit by hand.

## Why these balls

Each signal's destination is taken from the board itself: the
FPGA-side pad of the buffer's 22R series pack for data bits, buffer
pin 2 for `_DIR`, and the pull-up end of the already-routed `_OE`
trace for `_OE`. Balls are then handed to bundles as contiguous arcs
around the die, and matched within each arc in order, so nets leave
the package in the same sequence as their destinations.

Banks that carry LVDS pairs are capped at **14 GPIO** each (Trion rule). On this package those are the top banks
`BANK2A`-`2F` (`GPIOT_*`) and the bottom banks `BANK4A`-`4F`
(`GPIOB_*`); the left and right banks carry no pairs and are
uncapped. The cap counts every GPIO in the bank, so held pins
(configuration, JTAG, the dedicated clock input) come off the
budget before the optimiser sees it.

`BANK3E` (74 balls, the right flank) is excluded: it is the DDR bank
and `VCCIO_DDR` is unconnected, so it cannot be a 3.3 V I/O bank.
R0/R1/R2 are therefore fed from the top-right and bottom-right
corners. Those DDR balls carry no nets and no vias, so the copper
beneath them is an open channel on the inner signal layers.

## Downstream

`nuBoard/fpga_pin_map.csv` carries the same table as
`Signal,GPIO,Ball,Bank,Group` for the Efinity flow. Note that
`scripts/gen_isf.py` currently targets **T20F256** (the T20_Rig
board) and does not read this file; pointing it at T120F484 is a
separate job.
